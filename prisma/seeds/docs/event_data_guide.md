# WISH OS 데이터 표준화 가이드 (Ver. 2026)

이 문서는 `WISH OS` 아카이빙 데이터의 일관성을 유지하고, 시스템 간의 참조 무결성을 보장하기 위한 **데이터 입력 규칙(Convention)**을 정의합니다.

**최종 업데이트:** 2026-01-17

---

## 1. Program (방송 프로그램) 표준화

`Program` 모델은 `Event`와 연결되는 기준 정보(Master Data)입니다. 
**UI 표시용 이름**과 **매칭용 키(Key)**를 명확히 구분합니다.

### 1-1. 필드 정의 규칙
| 필드명 | 설명 | 규칙 | 예시 |
| :--- | :--- | :--- | :--- |
| **`name`** | **[Key]** 매칭용 고유 명칭 | 괄호/특수문자 제외. **한국어 명칭**을 최우선으로 사용. | `엠카운트다운`, `CDTV 라이브! 라이브!` |
| **`displayName`** | **[UI]** 화면 표시용 명칭 | 원어, 약칭 등을 포함한 풀네임. | `엠카운트다운 (M COUNTDOWN)`, `CDTV ライブ! ライブ!` |
| **`network`** | 방송사 | 영문 대문자 약칭 사용. (웹예능은 'YouTube') | `SBS M`, `TBS`, `YouTube` |
| **`airTime`** | 방송 시간 | **30시간제(25시, 26시)** 문자열 표기 허용. | `'18:00'`, `'25:30'` |

### 1-2. 국가별 입력 가이드
* **한국(KR):** 줄임말 대신 **정식 명칭**을 `name`으로 사용 (예: `음악중심` (X) -> `쇼! 음악중심` (O))
* **일본(JP):** `name`은 무조건 **한국어 발음/표기**를 기준으로 함. (개발 편의성 및 정렬 목적)
    * Good: `name: '뮤직 스테이션'`, `displayName: '뮤직 스테이션 (M스테)'`

### 1-3. 웹 예능 / 유튜브 콘텐츠
단발성 출연이 아닌, 고정 포맷이 있는 유명 웹 콘텐츠는 `Program`으로 등록하여 관리합니다.
* **Network:** `YouTube`
* **ProgramType:** `WEB_CONTENT`
* **예시:** `잇츠라이브`, `스튜디오 춤`, `아이돌 인간극장`, `문명특급`

## 2. Event (스케줄) 표준화 : 타이틀(Title) 규칙

모든 스케줄의 `title`은 **시스템이 파싱하기 쉬운 형태**여야 하며, `appearance` 정보는 `Program` 모델과 **정확히 일치**해야 합니다.

### 2-1. 방송 스케줄 (TV, Radio, Web)
**포맷:** `[방송사] 프로그램명 (상세내용)`

| 상황 | 규칙 | 예시 |
| :--- | :--- | :--- |
| **기본** | `[방송사] 프로그램명` | `[SBS M] 더 쇼` |
| **웹 예능** | `[채널명] 콘텐츠 제목` | `[Studio CHOOM] BE ORIGINAL 'WISH'` |
| **공동 송출** | `[방송사1/방송사2] 프로그램명` | `[ENA/NTV] NCT Universe : LASTART` |
| **라디오 코멘트** | `[방송사] 프로그램명 (코멘트)` | `[TOKYO FM] ONE MORNING (코멘트)` |
| **특수 회차** | `(Ep.x)` 또는 `(역할)` 병기 | `[MBC] 쇼! 음악중심 (스페셜 MC 시온)` |

### 2-2. 릴리즈 (Release) : 음원/음반/영상
**포맷:** `[Type] 제목` (서술어 제외, 명사형 종결)

| 타입 | 설명 | 예시 |
| :--- | :--- | :--- |
| **`[Album]`** | **디지털 음원** 발매 (메인) | `[Album] 싱글 1집 《WISH》` |
| **`[Physical]`** | **실물 음반** 발매 (CD, 플랫폼 등) | `[Physical] 싱글 1집 《WISH》 (CD)` |
| **`[MV]`** | 공식 뮤직비디오 | `[MV] WISH (Korean Ver.)` |
| **`[Teaser]`** | 티저 (영상/이미지) | `[Teaser] Hands Up (Image)` |
| **`[Pre-release]`** | 선공개 곡 | `[Pre-release] 선공개곡 《Dunk Shot》` |
| **`[Performance]`** | 퍼포먼스 비디오 | `[Performance] NASA` |

### 2-3. 공지 및 판매 (Announcement)
**포맷:** `[Prefix] 제목`

| 타입 | 설명 | 예시 |
| :--- | :--- | :--- |
| **`[Pre-order]`** | 예약 판매 시작 | `[Pre-order] 싱글 1집 《WISH》` |
| **`[Announcement]`** | 일반 공지 | `[Announcement] 공식 팬클럽 모집 안내` |
| **`[Pop-up]`** | 팝업 스토어 | `[Pop-up] WISH STATION in SEOUL` |
| **`[Event]`** | 이벤트/럭키드로우 | `[Event] 발매 기념 럭키 드로우` |

## 3. 시간 및 날짜 표기 가이드 (중요)

일본 방송의 30시간제(25시, 26시)와 글로벌 시차를 다루는 규칙입니다.

### 3-1. DB 저장 규칙 (`Event` 모델)
* **`date` (날짜):** 무조건 **실제 달력 날짜(Real Date)**를 입력합니다. (타임라인 정렬용)
    * *예: 수요일 26시 방송 -> **목요일** 날짜로 저장*
* **`time` (시간):** `String` 타입이므로 **24시간제**(`02:00`)와 **30시간제**(`26:00`) 모두 허용하나, **정렬을 위해 24시간제 환산(`02:00`)** 입력을 권장합니다.

### 3-2. 설명 및 표시
* 팬들의 혼동을 막기 위해 `description` 필드에 방송사 표기 시간을 병기합니다.
    * *예: "수요일 26:00 방송 (목요일 02:00)"*

## 6. 분류 기준: ContentType vs ExternalLinkType

데이터 입력 시 가장 먼저 결정해야 할 것은 **"이것이 '영상(볼거리)'인가, '링크(이동버튼)'인가?"**입니다.

### 6-1. 구분 원칙 (Decision Tree)
| 질문 | 모델 | 설명 | UI 예시 |
| :--- | :--- | :--- | :--- |
| **"사용자가 클릭해서 영상을 시청하는가?"** | **`Content`** | 유튜브, 숏폼, 다시보기 등 미디어 그 자체 | 썸네일 카드, 플레이어 |
| **"사용자가 클릭해서 외부 페이지로 이동하는가?"** | **`ExternalLink`** | 기사, 예매처, SNS 프로필, 스트리밍 | 아이콘 버튼, 텍스트 링크 |

### 6-2. 상세 타입 가이드

#### 🅰️ ExternalLinkType (정보 및 이동)
| 타입 | 용도 | 예시 |
| :--- | :--- | :--- |
| **`OFFICIAL`** | 공식 홈페이지, 팬클럽 공지 | SMTOWN 공식 홈, 일본 공홈 |
| **`SNS`** | 소통 채널, 멤버 포스트 | X(트위터), 인스타 프로필, **위버스 피드/포스트** |
| **`NEWS`** | 텍스트 기반 정보 | 뉴스 기사, 매거진 인터뷰 텍스트 |
| **`STREAMING`** | 음원 감상 페이지 | 멜론, 스포티파이, 애플뮤직 앨범 링크 |
| **`TICKET`** | 티켓 예매 페이지 | 티켓링크, 인터파크, 예스24 |
| **`STORE`** | 굿즈/앨범 판매처 | SM STORE, 위버스샵 |

#### 🅱️ ContentType (미디어 아카이빙)
| 타입 | 용도 | 주요 플랫폼 |
| :--- | :--- | :--- |
| **`MV`** | 공식 뮤직비디오 | YouTube |
| **`PERFORMANCE`** | 무대 영상 (음방, 직캠, 퍼포먼스 비디오) | YouTube |
| **`WEB_VARIETY`** | 자체 콘텐츠 (자컨), 웹 예능 | YouTube |
| **`BEHIND`** | 자켓/MV 촬영 비하인드, 레코딩 | YouTube |
| **`LIVE_STREAM`** | 라이브 방송 다시보기 | **Weverse**, YouTube |
| **`CHALLENGE`** | 안무/댄스 위주의 숏폼 | YouTube, TikTok |
| **`SHORTS`** | 비주얼, 유머, 비하인드 숏폼 | YouTube, TikTok |

## 6-3. 숏폼 분류 기준 (Shorts vs Challenge)

세로형 숏폼 영상은 **"춤의 목적"**에 따라 엄격하게 구분합니다.

### A. `CHALLENGE` (챌린지)
* **정의:** **"안무(Dance)"**를 보여주거나 홍보하는 것이 주목적인 영상.
* **해당 조건 (하나라도 충족 시):**
    1.  제목에 **`w/` (With)**가 포함됨 (타 아티스트 합방).
    2.  본인 곡(`WISH`) 또는 타 가수 곡의 **공식 안무**를 춤.
    3.  유행하는 댄스 챌린지 커버 (제대로 된 안무 소화).
* **예시:** `#ItsMyWISH w/ KEY`, `Smoke Challenge`, `Slickback (Dance Ver.)`

### B. `SHORTS` (일반 쇼츠)
* **정의:** 춤이 메인이 아니거나, 분위기/유머/비하인드 위주의 영상.
* **해당 조건:**
    1.  단순한 율동, 장난, 상황극, 연기.
    2.  얼굴 위주의 비주얼 영상 (`Concept Shorts`).
    3.  캐릭터(위츄) 영상.
* **예시:** `Cat Walk (Meme)`, `Who's that sexy bread?`, `Cute Moment`

## 6-4. 플랫폼별 처리 가이드 (Weverse & YouTube)

### A. Weverse (위버스)
위버스는 기능에 따라 모델을 분리합니다.
* **📺 위버스 라이브 (Live):** `Content` 모델 (`LIVE_STREAM`)
* **📝 멤버 포스트/모먼트:** `ExternalLink` 모델 (`SNS`)
* **📰 위버스 매거진:** `ExternalLink` 모델 (`NEWS`)

### B. YouTube (유튜브)
* **공식 MV/티저:** `Content` (`MV`, `TEASER`)
* **음방 무대/직캠:** `Content` (`PERFORMANCE`, `FANCAM`)
* **자체 예능:** `Content` (`WEB_VARIETY`)
